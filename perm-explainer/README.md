# perm-explainer

权限卡片弹出后，在它上面再弹一个解释框：作用 / 影响 / 风险。

- 卡片本身不变：原命令、拒绝 / 允许一次 / 始终允许，全都在。
- 只对**高危命令**触发（`rm`、`git push`、`sudo`、`curl | sh`、改注册表、装软件等）。
- 如果命令被 auto 模式自动放行、根本没弹卡片，插件也不会弹框——
  它用"解释写完了吗 / 调用结束了吗"来竞速判断，不会打扰静默通过的调用。
- 解释生成失败或弹框失败时静默跳过，绝不影响授权本身。

## 安装

```
/plugin install perm-explainer --marketplace AAAYNMMM/claude-plugins
```

## 工作原理（一句话）

`tool.call` 钩子先调用 `next(e)` 但不立刻返回，此时权限卡片已经弹出并等待；
趁这段时间生成解释，用 `$.ui.ask` 弹一个框盖在卡片上；你看完关掉，再在卡片上做决定。

## 调参

都在 `hooks/register.ts` 顶部：

| 常量 | 作用 |
|---|---|
| `RISKY_PATTERNS` | 哪些命令算高危、需要生成解释；想扩缩范围就改这个数组 |
| `MODEL` / `FALLBACK_MODEL` | 生成解释用的模型，必须是环境允许列表里的完整 id |
| `TIMEOUT_MS` | 单次模型调用的超时，默认 6 秒 |
| `MAX_TOKENS` | 解释长度上限 |
| `SYSTEM` | 提示词，想改解释的格式或语气就改这里 |

## 诊断

日志写在插件自己所在的目录：`perm-explainer.log`（仓库已忽略 `*.log`）。
每行记录一次触发：是否高危、解释是否生成、解释框是否显示成功。

## 已知限制

- 桌面版权限卡片不接受插件额外加的文字：`reason` 字段和 `$.ui.notice` 都实测无效，
  所以只能用"另弹一个框"的方式。
- 必须先让卡片出现、再弹框，否则 `$.ui.ask` 会替代系统卡片、
  令「允许一次 / 始终允许」消失。
- 因此这个解释框是纯展示：关掉它之后，仍要在下面的卡片上做真正的决定。
